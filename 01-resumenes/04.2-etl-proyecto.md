# Proyecto ETL  
Tópicos Avanzados de Bases de Datos  
Versión neutral y técnica (Python + SQL)

Este documento describe la tarea que los estudiantes deberán realizar para el módulo ETL del curso Tópicos Avanzados de Bases de Datos. La especificación es completamente neutral: no impone un dominio específico como ventas, alquileres, remates, censo, etc. Cada estudiante podrá elegir el dominio que prefiera, siempre que cumpla los requisitos técnicos establecidos.

El proyecto debe realizarse exclusivamente con:
- Python
- SQL (PostgreSQL, SQL Server o MySQL)

---

## 1. Objetivo general

Implementar un proceso ETL completo utilizando un dominio libre, construyendo una base de datos con seis tablas, generando datos masivos, migrando información hacia un modelo dimensional y graficando los resultados con Python.

---

## 2. Requisitos técnicos obligatorios

### 2.1 Base de datos con seis tablas

El proyecto debe incluir:

- Una tabla de transacciones con al menos 10 000 registros.
- Cuatro tablas adicionales que funcionarán como dimensiones.
- Una tabla de hechos que consolide la información transformada.

En total, el diseño debe quedar conformado por seis tablas: una tabla de transacciones, cuatro dimensiones y una tabla de hechos.

Los nombres de las tablas dependen del dominio elegido por el estudiante.  
Ejemplos de nombres genéricos:

- TransaccionesRaw  
- DimEntidadA  
- DimEntidadB  
- DimTiempo  
- DimCategoria  
- FactEventos  

El estudiante puede renombrarlas según su dominio.

---

## 3. Tabla de transacciones (obligatoria)

La tabla de transacciones debe contener al menos 10 000 registros.  
Los datos deben generarse con:

- Python  
- SQL (PostgreSQL, SQL Server o MySQL)

La estructura mínima recomendada incluye:

- Fecha  
- Identificador de entidad principal  
- Identificador de entidad secundaria  
- Cantidad o medida  
- Valor numérico  
- Otros atributos relevantes del dominio

Ejemplos de nombres genéricos:

- TransaccionesRaw  
- EventosOriginales  
- MovimientosBrutos  
- RegistrosFuente  

---

## 4. Dimensiones

El estudiante debe crear cuatro dimensiones, cuyos nombres y atributos dependerán del dominio elegido.

Ejemplos genéricos:

- DimEntidadA  
- DimEntidadB  
- DimTiempo  
- DimCategoria  

Cada dimensión debe tener:

- Una clave primaria  
- Atributos descriptivos  
- Datos derivados del proceso ETL

---

## 5. Tabla de hechos

La tabla de hechos debe consolidar la información transformada y contener claves foráneas hacia las dimensiones.

Ejemplos genéricos:

- FactEventos  
- FactMovimientos  
- FactTransacciones  

Debe incluir:

- Claves foráneas hacia las dimensiones  
- Medidas numéricas  
- Atributos relevantes del dominio  

---

## 6. Proceso ETL

El estudiante debe implementar un proceso ETL completo:

### 6.1 Extracción
Leer los datos desde la tabla de transacciones masiva.

### 6.2 Transformación
Aplicar limpieza, normalización, enriquecimiento y derivación de atributos.

### 6.3 Carga
Insertar los datos transformados en:

- Las tablas de dimensiones  
- La tabla de hechos  

El ETL debe implementarse con:

- Python  
- SQL (PostgreSQL, SQL Server o MySQL)

No se permiten otras herramientas ETL.

---

## 7. Graficación de resultados

El estudiante debe generar al menos dos gráficos basados en los datos procesados.  
Los gráficos deben ser:

- Simples  
- Claros  
- Entendibles  
- Adecuados para un taller de bases de datos  
- No deben ser gráficos elaborados ni de sistemas de información

Herramienta obligatoria:

- Python (matplotlib, seaborn o pandas)

Ejemplos de gráficos aceptables:

- Conteo por categoría  
- Tendencia temporal  
- Distribución de valores  
- Comparación simple entre dos dimensiones
