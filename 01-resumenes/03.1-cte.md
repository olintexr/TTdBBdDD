# README.md — Introducción a CTE en SQL Server

## 1. Objetivo

Este módulo presenta de forma práctica qué es un CTE (Common Table Expression), por qué sirve y cómo ayuda a escribir consultas más claras, ordenadas y eficientes.

El enfoque principal será mostrar una comparación entre:

- una consulta tradicional con JOIN y WHERE,
- una solución usando tabla temporal,
- y una solución usando CTE.

---

## 2. Base de datos para reproducir el ejemplo

Antes de ejecutar los ejemplos, puede crear las tablas necesarias y agregar unos pocos registros.

```sql
IF OBJECT_ID('dbo.Cuenta', 'U') IS NOT NULL DROP TABLE dbo.Cuenta;
IF OBJECT_ID('dbo.Interesado', 'U') IS NOT NULL DROP TABLE dbo.Interesado;
IF OBJECT_ID('dbo.Sucursal', 'U') IS NOT NULL DROP TABLE dbo.Sucursal;
GO

CREATE TABLE Sucursal (
    SucursalID INT IDENTITY(1,1) PRIMARY KEY,
    ciudad_sucursal VARCHAR(50) NOT NULL,
    activos DECIMAL(10,2) NOT NULL
);
GO

CREATE TABLE Cuenta (
    CuentaID INT IDENTITY(1,1) PRIMARY KEY,
    numero_cuenta VARCHAR(20) NOT NULL,
    saldo DECIMAL(10,2) NOT NULL,
    SucursalID INT NOT NULL REFERENCES Sucursal(SucursalID)
);
GO

CREATE TABLE Interesado (
    CuentaID INT PRIMARY KEY,
    ClienteID INT NOT NULL
);
GO

INSERT INTO Sucursal (ciudad_sucursal, activos) VALUES

GO

INSERT INTO Cuenta (numero_cuenta, saldo, SucursalID) VALUES

GO

INSERT INTO Interesado (CuentaID, ClienteID) VALUES

```

Con este conjunto de datos, el ejemplo del CTE podrá filtrar cuentas con saldo mayor a 4000 y luego unirlas con la tabla de sucursales.

## 3. Conceptos clave

### Glosario de las tablas

- **Sucursal**: almacena las sucursales del negocio. Cada sucursal tiene un identificador único llamado `SucursalID`.
- **Cuenta**: almacena las cuentas registradas en cada sucursal. Cada cuenta pertenece a una sucursal mediante `SucursalID`.
- **Interesado**: almacena los interesados o clientes relacionados con una cuenta. Cada fila se asocia a una cuenta mediante `CuentaID`.

### Relación entre tablas

```mermaid
flowchart LR
    Sucursal["Sucursal"] --> Cuenta["Cuenta"]
    Cuenta --> Interesado["Interesado"]
```

En otras palabras:

1. una sucursal puede tener muchas cuentas,
2. una cuenta puede estar relacionada con uno o varios interesados,
3. y el CTE nos ayuda a filtrar esa información antes de unir las tablas.

---

### ¿Qué es un CTE?

Un CTE es una tabla temporal lógica que existe solo dentro de una consulta. Sirve para:

- organizar mejor el código,
- evitar subconsultas repetidas,
- separar pasos lógicos de una consulta,
- y facilitar la lectura del query.

### ¿Cuándo usarlo?

Se recomienda usar un CTE cuando se quiere:

- filtrar datos antes de unir tablas,
- dividir una consulta compleja en pasos,
- o preparar un conjunto intermedio para trabajar con él más fácilmente.

### Ventaja principal

El CTE permite pensar la consulta como una secuencia de pasos:

1. primero se prepara el conjunto de datos,
2. luego se trabaja con ese conjunto,
3. y finalmente se obtiene el resultado final.

---

## 3. Problema de la consulta inicial

La consulta siguiente hace primero el JOIN y luego aplica el filtro con WHERE.

```sql
SELECT 
    sucursal.SucursalID, 
    sucursal.ciudad_sucursal,
    sucursal.activos,
    cuenta.numero_cuenta, 
    cuenta.saldo
FROM sucursal 
LEFT JOIN cuenta ON sucursal.SucursalID = cuenta.SucursalID
WHERE cuenta.saldo > 4000;
```

### ¿Qué problema hay?

Si el JOIN genera muchas filas y después el WHERE elimina la mayoría, el motor debe hacer mucho trabajo innecesario.

En términos simples:

- primero une tablas,
- después descarta registros,
- y eso puede consumir más CPU y memoria de lo necesario.

Una forma más eficiente es:

1. filtrar primero los datos relevantes,
2. y luego unirlos con la otra tabla.

---

## 4. Enfoque 1: usar tabla temporal

Una tabla temporal es una tabla de corta duración que existe durante la sesión actual.

### Ventajas

- permite revisar los datos intermedios,
- puede reutilizarse varias veces,
- y se pueden crear índices si se necesita.

### Desventaja

- requiere crearla y eliminarla manualmente.

### Ejemplo

```sql
-- Guardamos en una tabla temporal las cuentas con saldo mayor a 4000
SELECT 
    numero_cuenta,
    saldo,
    SucursalID
INTO #tmp_cuenta
FROM cuenta
WHERE saldo > 4000;
GO

-- Revisamos el contenido de la tabla temporal
SELECT * FROM #tmp_cuenta;
GO

-- Ahora hacemos el JOIN con la tabla temporal
SELECT 
    sucursal.SucursalID, 
    sucursal.ciudad_sucursal,
    sucursal.activos,
    cuenta.numero_cuenta, 
    cuenta.saldo
FROM sucursal
INNER JOIN #tmp_cuenta AS cuenta
    ON sucursal.SucursalID = cuenta.SucursalID;
GO

-- Eliminamos la tabla temporal
DROP TABLE #tmp_cuenta;
GO
```

### Explicación paso a paso

1. Se filtran las cuentas con saldo mayor a 4000.
2. Ese resultado se guarda en una tabla temporal.
3. Luego se une esa tabla temporal con la tabla sucursal.
4. El resultado final ya no necesita un WHERE adicional.

---

## 5. Enfoque 2: usar CTE

Un CTE es una solución más limpia cuando no se necesita reutilizar el resultado varias veces.

### Ventajas

- no requiere DROP TABLE,
- mejora la legibilidad del query,
- y permite dividir la consulta en pasos claros.

### Desventaja

- no se puede reutilizar fuera del mismo query.

### Ejemplo básico

```sql
;WITH cte_cuenta AS (
    SELECT
        numero_cuenta,
        saldo,
        SucursalID
    FROM cuenta
    WHERE saldo > 4000
)
SELECT 
    sucursal.SucursalID, 
    sucursal.ciudad_sucursal,
    sucursal.activos,
    cuenta.numero_cuenta, 
    cuenta.saldo
FROM sucursal
INNER JOIN cte_cuenta AS cuenta
    ON sucursal.SucursalID = cuenta.SucursalID;
GO
```

### Explicación paso a paso

1. El CTE se define con `WITH`.
2. Dentro del CTE se filtran las cuentas con saldo mayor a 4000.
3. Luego, en la consulta principal, se usa ese resultado como si fuera una tabla.
4. El código queda más claro porque el filtro aparece primero.

---

## 6. Comparación rápida

| Opción | Cuándo usarla | Ventaja principal |
|---|---|---|
| JOIN + WHERE | Consultas sencillas | Fácil de escribir |
| Tabla temporal | Cuando se necesita reutilizar o inspeccionar datos intermedios | Más flexible |
| CTE | Cuando la consulta se entiende mejor en pasos | Muy legible y limpio |

---

## 7. Ejemplo avanzado con varios CTE

Los CTE también pueden encadenarse. Esto permite construir consultas más complejas de manera ordenada.

```sql
;WITH 
cte_filtro_cuenta AS (
    SELECT CuentaID
    FROM Interesado
    WHERE ClienteID IN (2)
),
cte_cuenta AS (
    SELECT
        cuenta.numero_cuenta,
        cuenta.saldo,
        cuenta.SucursalID
    FROM cuenta
    INNER JOIN cte_filtro_cuenta
        ON cuenta.CuentaID = cte_filtro_cuenta.CuentaID
    WHERE cuenta.saldo > 4000
)
SELECT 
    sucursal.SucursalID,
    sucursal.ciudad_sucursal,
    sucursal.activos,
    cuenta.numero_cuenta,
    cuenta.saldo
FROM sucursal
INNER JOIN cte_cuenta AS cuenta
    ON sucursal.SucursalID = cuenta.SucursalID;
GO
```

### ¿Qué ocurre aquí?

1. Primero se crea un CTE con una lista de cuentas filtradas.
2. Después se usa ese resultado para filtrar aún más las cuentas.
3. Finalmente se une con la tabla sucursal.

Este patrón es muy útil cuando la lógica necesita varios pasos intermedios.

---

## 8. Resumen final

Un CTE es una herramienta muy útil para:

- mejorar la legibilidad del código,
- separar la lógica en pasos claros,
- y filtrar datos antes de hacer JOINs grandes.

### Regla práctica

- Si el resultado intermedio solo se necesita una vez, usar CTE.
- Si se necesita reutilizar o inspeccionar ese resultado, usar tabla temporal.
