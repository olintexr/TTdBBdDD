# Ejercicio: Proyecto final de bases de datos — Sistema de biblioteca + Data Warehouse

## Objetivo

Desarrollar un módulo SQL completo que integre diseño de tablas, consultas, vistas, CTE, tablas temporales, stored procedures, triggers, transacciones y un modelo analítico tipo Data Warehouse.

## Alcance del ejercicio

### 1. Crear una base de datos autocontenida

El script debe:

- crear la base de datos,
- cambiar el contexto a esa base,
- y limpiar defensivamente los objetos si ya existen.

### 2. Diseñar el modelo OLTP

Crear las tablas principales del sistema de biblioteca:

- `Autor`
- `Area`
- `Obra`
- `Libro`
- `Usuario`
- `Prestamo`
- `DetallePrestamo`
- `ObraAutor`

### 3. Definir relaciones correctamente

El modelo debe reflejar que:

- una obra pertenece a un área,
- una obra puede tener uno o varios autores,
- un libro es un ejemplar físico asociado a una obra,
- un usuario alquila libros,
- y un préstamo puede incluir varios libros.

### 4. Insertar datos iniciales

El script debe incluir inserts con datos de prueba.

Se recomienda incluir al menos:

- varios autores,
- varias áreas,
- varias obras,
- varios libros,
- varios usuarios,
- y varios préstamos con detalle.

## Requisitos del ejercicio

### 5. Consultas y joins

El script debe incluir consultas con:

- `INNER JOIN`,
- `LEFT JOIN`,
- `RIGHT JOIN`,
- y una consulta conceptual de `FULL JOIN` si aplica.

### 6. Crear vistas

Crear al menos dos vistas:

1. una vista de libros extendidos con:
   - título de la obra,
   - área,
   - cantidad de autores.

2. una vista de préstamos extendidos con:
   - usuario,
   - fechas,
   - y estado del préstamo.

### 7. Crear CTE

Incluir al menos:

- un CTE para filtrar libros muy solicitados,
- un CTE para identificar préstamos vencidos,
- y un ejemplo de CTE encadenado.

### 8. Crear tablas temporales

Incluir una tabla temporal para almacenar un resultado intermedio y luego usarla en una consulta.

### 9. Crear stored procedures

Implementar al menos tres stored procedures:

- `sp_registrar_libro`
  - validar existencia,
  - insertar el libro,
  - y asociarlo a la obra.

- `sp_registrar_prestamo`
  - validar disponibilidad del libro,
  - validar usuario,
  - y manejar errores con `TRY/CATCH`.

- `sp_devolver_libro`
  - validar préstamo activo,
  - y actualizar el estado.

### 10. Crear triggers

Implementar triggers para validar reglas de negocio, por ejemplo:

- evitar préstamos duplicados del mismo libro,
- evitar marcar un libro como disponible si aún tiene préstamos activos,
- o validar fechas de préstamo y devolución.

### 11. Manejar transacciones

Incluir ejemplos con:

- `BEGIN TRAN`,
- `COMMIT`,
- `ROLLBACK`,
- y `XACT_ABORT`.

### 12. Diseñar un modelo analítico tipo Data Warehouse

Incluir una propuesta conceptual de:

- dimensiones: `DimLibro`, `DimObra`, `DimAutor`, `DimArea`, `DimUsuario`, `DimFecha`
- y una tabla de hechos: `HechoPrestamo`

También deben incluirse:

- métricas como cantidad de préstamos,
- días de préstamo,
- y un indicador de atraso.

### 13. Incluir ETL conceptual

Explicar de forma breve el proceso de:

- extracción desde el modelo OLTP,
- transformación de datos,
- y carga en el modelo analítico.

### 14. Incluir consultas analíticas

Agregar consultas para responder preguntas como:

- libros más prestados,
- obras más consultadas,
- áreas más demandadas,
- autores más leídos,
- usuarios con mayor actividad,
- y préstamos por periodo.

### 15. Incluir pruebas del módulo

El script debe terminar con pruebas mínimas para verificar:

- inserción de datos,
- registro de préstamos,
- devolución de libros,
- ejecución de vistas,
- ejecución de CTE,
- validación de triggers,
- y verificación de integridad.

## Recomendaciones

- Organizar el script en secciones con comentarios.
- Usar nombres claros para tablas, columnas y objetos.
- Mantener el script autocontenido y ejecutable.
- Priorizar claridad y orden sobre complejidad excesiva.

## Resultado esperado

Un script SQL completo, bien organizado, que demuestre dominio de:

- diseño OLTP,
- integridad referencial,
- consultas relacionales,
- vistas,
- CTE,
- tablas temporales,
- procedimientos almacenados,
- triggers,
- transacciones,
- y un enfoque analítico tipo Data Warehouse.
